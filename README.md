## 01. 프로젝트 배경

1·2인 가구의 소규모 장보기와 식비 부담을 출발점으로, 자취생의 두 가지 고민에 집중했습니다.

- **오늘 뭐 먹지?** 냉장고에 남아 있는 재료부터 활용하고 싶다.
- **하나 더 뭐 살까?** 꼭 필요한 재료만 사면서 만들 수 있는 메뉴를 늘리고 싶다.

단순히 평점이 높은 요리를 나열하기보다 **보유 재료 활용, 추가 구매 부담, 조리시간, 사용자 취향**을 함께 고려합니다.

레시피 ID를 기준으로 두 원본 데이터를 연결합니다. 실제 추천 후보는 사용자의 조건과 식사 적합성 규칙에 따라 추가로 선별합니다.

## 03. EDA 및 전처리

| 확인한 내용 | 처리 및 활용 |
|---|---|
| 평점은 4~5점에 집중되고, 0점이 약 5.37% 존재 | 0점 리뷰의 의미를 감성분석으로 확인 |
| 영양성분·조리시간·평가량의 우측 편향 | 영양성분 7종, 조리시간, 평가·리뷰 개수에 `log1p` 적용; 평점은 원척도 유지 |
| 레시피 이름 결측 1건 | 해당 레시피 제거 |
| 리뷰 텍스트 결측 | 평점 정보가 있으므로 행은 유지 |
| 조리시간 0분에 미입력 가능성 | 등록연도·조리 단계·가열 표현을 점검해 정제하고, 추천 범위는 `0 < minutes ≤ 60`으로 제한 |
| 재료명의 다양한 표기 | 소문자·공백 정리, 단·복수 및 형태 표현 통합 |
| 레시피별 평가 수 편차 | 평가 수를 반영하는 베이지안 평점 생성 |

베이지안 평점은 레시피 평균 `R`, 평가 수 `v`, 전체 평균 `C`, 사전 가중치 `m`을 사용합니다. 발표에서는 `C=4.5406`, 평가 수 중앙값인 `m=2`를 기준으로 설명했습니다.

```text
Bayesian Rating = (v × R + m × C) / (v + m)
```

### 레시피 구성 탐색: K=6

재료 목록을 **TF-IDF → SVD → K-means** 순서로 변환해 데이터의 구성을 살펴봤습니다. 발표에서는 음료·스무디형, 오일·마늘 기반형, 베이킹·디저트형, 조미형 메인요리, 일반 가정식형, 국물·기본 식재료형의 여섯 패턴으로 해석했습니다.

이 군집은 **EDA용**이며, 아래 취향 선택용 **K=16** 군집과 구분합니다.

## 04. 가설검정과 추천 설계에 반영한 점

아래 수치와 해석은 최종 발표 자료 기준입니다.

| 가설 | 주요 결과 | 해석 및 활용 |
|---|---|---|
| 보유 재료 수에 따라 재료 추가의 효과가 달라지는가? | 5·7·9개 조건에서 각각 100회 반복. Kruskal–Wallis `p=0.9623`, 효과크기 `ε²=0` | 보유 재료 개수만으로 증가 효과를 설명하기 어려움. 실제 재료 조합에서 새로 열리는 메뉴 수를 계산 |
| 0점 평점은 부정적 평가인가? | 0점 리뷰 60,847건 중 긍정 66.44%, 중립 17.49%, 부정 16.07% | 0점을 모두 불만으로 취급하지 않음. 발표의 평점 처리 기준에서는 긍정·중립 51,067건을 평점 계산에서 제외 |
| 영양성분은 인기도·만족도와 관련이 있는가? | FDR 보정 후 12개 항목에서 유의하지만 `|ρ| ≤ 0.038`. 그룹 비교 효과크기도 매우 작음 | 통계적 유의성과 실제 설명력을 구분. 영양성분을 추천의 핵심 점수로 채택하지 않음 |

0점 리뷰 분석에는 사전학습 모델 **`cardiffnlp/twitter-roberta-base-sentiment-latest`**를 사용했습니다. 감성 라벨은 모델의 예측값이며 실제 작성 의도를 확정하는 정답은 아닙니다.

## 05. 추천 모델

### 공통 후보 생성

사용자 입력은 **보유 재료 · 제외 재료 · 최대 조리시간 · 추가 구매 범위 · 선호 메뉴(선택 사항)**입니다.

- 기본 양념 47종을 별도 구매가 필요 없는 재료로 취급합니다.
- 소스·음료·요리 팁 등 식사로 보기 어려운 레시피를 제외합니다.
- 메인 재료와 부재료를 구분하고, 보유 메인 재료가 적어도 하나 있는 후보를 탐색합니다.
- 제외 재료, 조리시간, 부족 재료 수 조건을 적용합니다.
- 재료 등장 빈도를 기반으로 수급 난이도를 설정해 구매 부담에 반영합니다.

메인 재료 판별은 5개 시나리오를 비교한 뒤 **RULE ❶+❷**를 채택했습니다. 양념·부재료만으로 식사 후보가 과도하게 추천되는 문제를 줄이는 목적입니다.

### 레시피 특징과 취향 선택

| 특징 | 역할 | 결합 가중치 |
|---|---|---:|
| 재료 TF-IDF | 재료의 중요도와 구성 표현 | 1.0 |
| Word2Vec · 50차원 | 재료 간 의미적 유사성 표현 | 1.0 |
| 카테고리 | 코스, 요리 유형, 주재료 그룹, 국가·지역 요리 정보 | 0.5 |

저장된 콘텐츠 행렬은 **168,035 × 12,769**입니다.

취향 선택 후보는 재료 TF-IDF에 SVD와 K-means를 적용한 **16개 군집**에서 군집당 대표 메뉴 3개를 선정해 구성합니다. 사용자가 고른 메뉴와 후보의 **코사인 유사도**를 추천에 반영하며, 여러 메뉴를 고르면 유사도의 평균을 사용합니다. 취향을 선택하지 않아도 기본 추천을 받을 수 있습니다.

### MODEL 01 · 오늘 뭐 먹지?

후보를 **바로 조리**와 **추가 구매 후 조리**로 나누고, 재료 활용도·구매 부담·취향·평점·시간을 결합해 순위를 정합니다.

| 점수 요소 | 추가 구매 트랙의 기본 가중치 |
|---|---:|
| 재료 점수 | 30% |
| 구매 부담 점수 | 25% |
| 취향 유사도 | 20% |
| 베이지안 평점 | 15% |
| 조리시간 | 10% |

바로 조리 트랙은 구매 부담 항목을 제외하고 가중치를 재정규화합니다. 취향을 선택하지 않으면 취향 항목도 제외하고 재정규화합니다. 추가 구매 트랙의 재료 점수에는 보유 재료 활용률과 레시피 재료 충족률을 함께 반영합니다.

마지막에는 **MMR 방식의 다양성 보정**으로 비슷한 메뉴가 반복되는 것을 줄입니다.

```text
선택 점수 = 0.9 × 추천 점수 − 0.1 × 이미 선택된 메뉴와의 최대 유사도
```

### MODEL 02 · 하나 더 뭐 살까?

1. 사용자 조건을 만족하면서 **부족한 재료가 정확히 1개인 레시피**를 찾습니다.
2. 같은 부족 재료끼리 묶어 **새로 만들 수 있는 메뉴 수**를 집계합니다.
3. 메뉴 확장 수가 많은 재료를 상위 3개까지 제안합니다.

자주 쓰이는 재료를 일괄 추천하는 대신 **현재 냉장고에서 선택지를 넓혀주는 재료**를 추천합니다. 장보기 순위 자체에는 개인 취향 점수를 반영하지 않습니다.

## 06. 웹 서비스

**재료 입력 → 취향 선택 또는 생략 → 레시피·장보기 추천**의 흐름으로 사용합니다.

- 냉장고 화면에서 보유 재료와 제외 재료를 입력합니다.
- 최대 조리시간과 추가 구매 범위를 설정합니다.
- 대표 메뉴에서 마음에 드는 메뉴를 최대 3개 선택합니다.
- 바로 조리 가능한 메뉴와 조금 더 사면 가능한 메뉴를 확인합니다.
- 하나 더 구매할 재료와 그 재료로 확장되는 메뉴를 확인합니다.

화면은 **HTML·CSS·JavaScript**, 서버는 **FastAPI**, 추천 계산은 **Python**으로 구현했습니다. 저장된 자산을 불러와 사용자의 입력에 맞춰 계산하며, 예시 CSV 결과를 고정 출력하는 방식이 아닙니다. 음식 사진은 실제 레시피 사진이 아닌 **유사 요리 참고 사진**을 포함합니다.

## 08. 한계와 개선 방향

- **국내 요리 반영 한계:** 해외 레시피 중심이라 국내 자취 식문화와 재료 접근성을 충분히 반영하지 못합니다.
- **평가 데이터 희소성:** 사용자·레시피 간 평가가 부족해 개인화 수준에 제약이 있습니다.
- **규칙과 예측의 한계:** 기본 양념 보유 가정, 재료 수급 난이도, 리뷰 감성 예측은 실제 사용자 상황과 다를 수 있습니다.

향후 국내 레시피와 사용자 피드백을 축적해 추천의 적합성과 개인화 수준을 개선하고자 합니다.
